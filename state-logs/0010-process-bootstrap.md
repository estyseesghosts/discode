# 0010 — Process bootstrap and command registration

- **Slice:** Add the process-level entrypoints needed to run the bridge and register its global commands safely.
- **Acceptance criteria:**
  - Add a guarded `src/index.ts` process entrypoint that loads validated environment configuration, creates the real Discord gateway, starts the runtime, and handles top-level failures without printing secrets or raw causes.
  - Add an explicit `src/register-commands.ts` deployment entrypoint that loads configuration, creates a Discord REST client, and registers the global `/project attach` and `/run new` payload without doing so on bot startup.
  - Add `npm run start` and `npm run register-commands` scripts using a reproducible TypeScript runner.
  - Add focused tests for bootstrap success/config failure, command registration delegation, no import-time side effects, and safe top-level error handling.
  - Document the live-smoke prerequisites: Discord application/bot, Message Content Intent, permissions, environment variables, global command propagation, and a reachable OpenCode server.
  - Do not add status messages, persistence, automatic discovery, reconnect/backoff, or hard-coded runtime IDs.
- **Context:** Starting from `c2e4b39` plus handoff commit `cf3d7f7`, the runtime composition is tested and safe, but there is no process entrypoint or explicit command-registration command. This is the final code slice before a live bot-account smoke test.
- **Changes:** Added `src/bootstrap.ts` and guarded `src/index.ts` for validated environment loading, real Discord client creation, runtime startup, and sanitized failure reporting. Added guarded `src/register-commands.ts` for explicit global command registration. Added `tsx` and `--env-file=.env` npm scripts, process-script tests, bootstrap/registration tests, and live-smoke documentation in `README.md`.
- **Verification:** `npm test` passed: 14 files, 164 tests. `npm run typecheck` passed. `git diff --check` passed. `tsx --env-file` forwarding was verified with a temporary environment outside the repository; no real `.env` was created. No lint or build scripts are defined yet.
- **Decisions:** Keep command registration separate from bot startup so the bot does not PUT commands on every boot. Use Node's explicit `--env-file=.env` through `tsx`; both scripts require a local `.env`. Keep entrypoint imports side-effect-free with `import.meta.url`/`process.argv[1]` guards. Keep top-level failure messages fixed and sanitized, even at the cost of limited diagnostics. Keep the production runtime dependency boundary in `bootstrap.ts` and the deployment boundary in `register-commands.ts`.
- **Risks / follow-ups:** No live Discord/OpenCode smoke test has been run because credentials and a reachable service were not available in the development environment. A missing `.env` fails at the Node flag before the sanitized reporter runs. Post-login Discord gateway failures are not logged, and terminal event-stream failures have no reconnect policy. In-memory bindings/runs are lost on restart. The next concrete slice is a live smoke test with user-provided credentials and OpenCode endpoint, followed by any narrowly scoped fixes it reveals. Keep status messages, persistence, discovery, and reconnect/backoff out of scope until that evidence exists.
