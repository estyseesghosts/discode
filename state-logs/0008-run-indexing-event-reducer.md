# 0008 — Session/run indexing and semantic event reduction

- **Slice:** Add an in-memory run registry and minimal semantic reducer for global OpenCode events.
- **Acceptance criteria:**
  - Represent root OpenCode sessions as runtime runs keyed by root session ID and project directory, separate from Discord bindings.
  - Index child sessions under explicitly registered root runs without automatic discovery of unknown sessions.
  - Resolve events in deterministic order: known session ID, known child parent ID, then an unambiguous directory match; ignore location/session-less or ambiguous events.
  - Reduce known activity/idle/error events to deterministic run states while leaving unknown event types unchanged.
  - Ensure returned run/outcome values are defensive and never retain message text or event payloads.
  - Add focused tests for multiple runs/projects, idempotent registration, child indexing/removal, resolution precedence, ambiguity, state transitions, malformed/unknown events, and payload hygiene.
  - Do not add Discord status updates, persistence, automatic session discovery, startup wiring, or new Discord commands.
- **Context:** Starting from `448297f` plus handoff commit `c054739`, the global event consumer preserves event session/location context. The next milestone step is to index known root sessions and reduce their semantic state without coupling runtime state to Discord bindings.
- **Changes:** Added `src/runtime/run-registry.ts` with root/session/directory indexes, explicit root registration, child-session indexing, immutable project directories, removal, state transitions, and defensive copies. Added `src/runtime/run-state.ts` with pure state reduction and payload-free synchronous event ingestion. Added 34 focused runtime tests covering independent runs, idempotency, child/grandchild indexing, location/session precedence, directory matching, ambiguity/unmatched directories, state transitions, malformed events, payload hygiene, and validation.
- **Clarification (2026-09-24):** The directory fallback applies only to events with no session ID. An event with an unknown session ID is never assigned by directory, even when the directory is unambiguous, because that would be automatic discovery rather than explicit indexing.
- **Verification:** `npm test` passed: 10 files, 131 tests. `npm run typecheck` passed. `git diff --check` passed. No lint or build scripts are defined yet.
- **Decisions:** Keep run identity equal to the root OpenCode session ID for compatibility with the existing `BindingStore.activeRunId` and message forwarding. Keep runtime state independent from Discord bindings and never import `BindingStore` from runtime. Register roots explicitly; index children only through known `parentID` values. Map activity to `working`, `session.idle` to `idle`, error-class events to `error`, and unknown types to no change. Flatten grandchildren onto the known root run. Keep exact trimmed directory matching for now; do not normalize paths ad hoc.
- **Risks / follow-ups:** Child events currently roll directly into the root state, so a child idle/error can affect the whole root; future run-state semantics may need per-child aggregation. Exact directory matching is sensitive to separators, case, symlinks, and trailing slashes. Run creation is not yet wired into the registry, and the event consumer is not yet wired to the reducer. The next concrete slice is a single runtime wiring boundary: construct one shared client, register newly created sessions in the run registry, route commands/messages through the shared state, and start the one global event consumer. Keep status messages, persistence, and automatic discovery out of scope.
